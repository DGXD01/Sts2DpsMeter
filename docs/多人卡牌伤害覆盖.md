# 多人卡牌伤害覆盖

## 基线

- 游戏版本：`0.107.1`
- 范围：全部声明 `CardMultiplayerConstraint.MultiplayerOnly` 的卡牌
- 多人专属总数：21 张
- 卡池分布：无色 11 张，角色卡池 10 张
- 反编译源码：`E:\Slay the Spire 2\辅助生成文件\DPS检测Mod\反编译\sts2-0.107.1`
- 数据整理日期：2026-09-20
- 暂不纳入本文档：遗物效果、药水效果、敌方能力、事件牌和 Token 牌

本文档中的“多人卡牌”专指 `MultiplayerOnly` 卡牌，不等同于“所有能在多人模式使用的卡牌”。本文记录静态代码路径和当前统计落点，不代表多人联机的玩家归属、事件顺序和最终伤害数值已经实机验证。

## 统计原则

1. 玩家造成的对敌伤害归实际造成伤害的卡牌 ID、能力、充能球、宠物或遗物。
2. 同一张牌的多次命中、多目标、升级版本和额外打出次数合并为同一稳定来源。
3. 卡牌本体自损单独记录，不计入对敌输出。
4. 队友获得的格挡、能量、抽牌、力量、锻造、生成牌、充能球和宠物不计入当前出牌玩家的对敌输出。
5. 队友后续打出的牌或宠物造成的伤害，归实际攻击牌或宠物控制玩家，不回溯给提供增益或生成来源的牌。
6. 力量、虚弱、脆弱、`FlankingPower`、`KnockdownPower` 等只改变最终伤害值或出牌次数，不拆分出独立的附加伤害来源。例如 2 点力量下“打击”造成 8 点，只记录“打击 8 点”，不额外记录“力量 2 点”。
7. 承伤缩放、伤害归零、掩护和减伤属于受击结算路径，不产生独立的对敌输出事件。
8. 静态覆盖完成不代表游戏内运行态验证完成；凡依赖多人网络同步或运行时模型链的项目均标记为待验证。

## 分类说明

### 对敌直接伤害

`GangUp`、`Knockdown`、`TagTeam` 均通过 `DamageCmd.Attack(...).FromCard(this)` 建立卡牌上下文，静态预期归实际卡牌 ID。

- `GangUp`：基础伤害，并根据目标本回合已受到的其他友方攻击次数增加伤害。
- `Knockdown`：造成直接伤害，并施加 `KnockdownPower`；后续命中该敌人的攻击仍归实际攻击牌，不归 `Knockdown`。
- `TagTeam`：造成直接伤害，并施加 `TagTeamPower`；其他玩家后续对该目标或敌方全体打出的攻击可能额外打出一次，额外伤害归实际打出的攻击牌。

### 卡牌本体自损

`DemonicShield` 通过 `CreatureCmd.Damage(... Owner.Creature ...)` 对自身造成 1 点不可格挡、无能力修正的伤害，再为队友提供格挡。

- 自损记录为 `DemonicShield` 的 `SelfLoss`。
- 为队友提供的格挡不产生对敌输出。
- 自损不计入 `DemonicShield` 的输出伤害。

### 队友辅助、生成与派生效果

以下卡牌没有卡牌本体对敌伤害：

- `BeaconOfHope`：自身获得格挡后，为其他队友提供该次格挡量一半的格挡。
- `BelieveInYou`：为目标队友提供能量。
- `Coordinate`：为目标队友施加临时力量；队友后续攻击归实际攻击牌。
- `HuddleUp`：为队友抽牌。
- `Lift`、`Rally`：为队友提供格挡。
- `Mimic`：按目标队友当前格挡为自己提供格挡。
- `EnergySurge`：为所有队友提供能量。
- `Ignition`：为目标队友引导 `PlasmaOrb`；后续充能球伤害或收益按实际来源处理。
- `HammerTime`：自身触发锻造时，把后续锻造效果复制给其他玩家；后续牌伤害归实际牌。
- `Largesse`：为目标队友生成一张无色牌；后续伤害归实际生成的卡牌。
- `GlimpseBeyond`：为队友生成 `Soul` 并加入抽牌堆；`Soul` 是零费抽牌 Token。
- `LegionOfBone`：为所有存活玩家召唤 `Osty`；后续宠物伤害归宠物拥有者。

### 伤害修正与承伤修饰

以下效果改变后续伤害数值、出牌次数或受击结果，但不产生独立输出来源：

- `Flanking`：施加 `FlankingPower`，使非施加者对该敌人的有来源攻击按层数倍率结算；最终伤害归实际攻击牌。
- `Knockdown`：施加 `KnockdownPower`，使非施加者对该敌人的有来源攻击按层数倍率结算；施加者不拆分队友后续伤害。
- `TagTeam`：施加 `TagTeamPower`，使其他玩家对目标的攻击可能额外打出一次；额外伤害归实际攻击牌。
- `Intercept`：为自身提供格挡并给队友施加 `CoveredPower`，使被掩护队友受到的有来源攻击伤害归零；同时施加者获得 `InterceptPower`，其自身受到的有来源攻击按覆盖人数放大。这是承伤修饰，不生成独立反击或转移伤害。
- `Tank`：施加者受到的有来源攻击伤害翻倍，其他队友获得 `GuardedPower`，受到的有来源攻击伤害减半。这是承伤修饰，不生成独立输出。
- `Sneaky`：其他玩家打出攻击牌时，能力所有者获得格挡；该效果不产生对敌伤害。

## 非多人专属牌的多人边界

全量扫描 `Core.Models.Cards` 后，非多人专属牌中只有以下值得在多人统计中单独说明：

- `Omnislice` 使用 `GetTeammatesOf(damageResult.Receiver)`，其中 `damageResult.Receiver` 是被攻击敌人，因此得到的是敌方阵营的其他可命中单位。这是敌方同阵营溅射，不是玩家队友复制段；后续伤害仍归 `Omnislice`。
- `Adrenaline` 和 `Nightmare` 使用 `LocalContext.IsMe` 只控制本地 VFX 或预览逻辑，不改变伤害来源或玩家归属。
- 其他普通卡牌可能生成牌、召唤宠物或施加增益；实际伤害仍按第 4 至第 6 条原则归实际来源。

## 当前代码落点

`DpsAttribution.cs` 当前提供以下伤害分类：

- `Output`：对敌输出。
- `Incoming`：玩家或宠物受到的伤害。
- `SelfLoss`：玩家或宠物受到的自损。
- `Ignored`：不纳入输出、受击或自损的事件。

`ResolveAccountablePlayer` 优先使用能力施加者、卡牌拥有者、充能球拥有者或宠物拥有者。当前代码没有为上述 21 张 `MultiplayerOnly` 卡牌增加专门硬编码；多人归属依赖 `DamageResult`、`CardModel.Owner`、`PowerModel.Applier` 和运行时模型链是否正确传递。

## 分类校验

- 多人专属总数：21 张。
- 卡池校验：`11 + 2 + 2 + 2 + 2 + 2 = 21`。
- 卡牌本体直接伤害：3 张，即 `GangUp`、`Knockdown`、`TagTeam`。
- 卡牌本体自损：1 张，即 `DemonicShield`。
- 无卡牌本体伤害：18 张。
- 直接伤害与自损交集：0 张。
- 多人专属能力产生的独立间接伤害：0 张。
- 逐卡编号：连续 `1..21`，类名唯一。
- 队友资源、生成物和承伤修饰的独立对敌输出：0 张。
- 力量及伤害倍率修正的独立来源：0 张。

## 待游戏内验证

- 在双人和三人以上对局中，`GangUp`、`Knockdown`、`TagTeam` 是否全部稳定归到对应卡牌 ID。
- `KnockdownPower`、`FlankingPower` 和 `TagTeamPower` 是否只改变伤害或出牌次数，且最终伤害归实际攻击牌和实际攻击玩家。
- `DemonicShield` 的自损是否进入 `SelfLoss`，且不计入任何玩家的对敌输出。
- `BeaconOfHope`、`BelieveInYou`、`Coordinate`、`HuddleUp`、`Lift`、`Mimic`、`Rally`、`EnergySurge` 是否不会生成错误的输出来源。
- `Ignition` 生成的充能球、`Largesse` 生成的牌、`GlimpseBeyond` 生成的 `Soul`、`HammerTime` 复制的锻造和 `LegionOfBone` 召唤的宠物是否按实际来源归档。
- `Intercept` 和 `Tank` 的承伤倍率是否只影响 `Incoming`，不会误增玩家输出。
- `TagTeamPower` 的额外出牌是否保留原攻击牌 ID、拥有者和目标关系。
- 双人、三人及更多玩家时，能力施加者、队友和宠物拥有者的 `AccountablePlayer` 是否一致。

## 当前限制

- 本文结论来自 `0.107.1` 程序集静态审计，尚未完成多人游戏内运行态验证。
- 遗物效果和药水效果不纳入本文档，后续按独立清单审计。
- 队友辅助类效果不会显示为当前玩家输出；如果未来需要统计“团队贡献”，必须新增独立指标，不能混入 DPS。
- 生成牌、共享宠物和网络同步下的所有权边界仍需实机验证。
- `DpsAttribution.cs` 没有多人专属专用映射；当运行时模型链、卡牌所有权或能力施加者缺失时，可能回退为能力来源、宠物来源或未知来源。
- 静态分类完整不代表多段攻击、死亡截断、目标切换、随机多目标和额外出牌已经完全验证。

# 药水效果统计

## 基线

- 游戏版本：`0.107.1`
- 反编译源码：`E:\Slay the Spire 2\辅助生成文件\DPS检测Mod\反编译\sts2-0.107.1`
- 药水模型目录：`MegaCrit.Sts2.Core.Models.Potions`
- 药水池目录：`MegaCrit.Sts2.Core.Models.PotionPools`
- 主药水目录的 `PotionModel` 文件：64 个
- 正式药水模型：63 个，含 Token 药水 `PotionShapedRock`
- 排除项：`DeprecatedPotion` 为废弃药水；`MockDiscardAndAddShivsPotion` 只存在于测试池，不属于正式药水
- 药水池登记：65 条，其中正式药水 63 条
- 数据整理日期：2026-09-20

本文档记录药水静态代码路径和当前 DPS 统计落点。结论来自游戏程序集反编译审计，不代表目标药水已经在单人、多人、随机目标或异步等待场景下完成游戏内验证。

## 统计原则

1. 药水本体直接对敌造成的伤害归药水来源。例如 `FirePotion` 的 20 点伤害显示为药水伤害，而不是施放药水前的最后一张卡。
2. 力量、敏捷、易伤、虚弱、缩小、暴击、格挡和承伤倍率只改变最终结算或资源量，不拆分独立附加伤害来源。例如 2 点力量的“打击”从 6 点变为 8 点，8 点全部计入“打击”，不额外记录 2 点力量来源。
3. 药水施加的中毒、灾厄、灭亡、荆棘等伤害型能力，后续伤害仍归实际伤害能力；已接入显式效果来源栈，唯一来源时可保留施加药水，混合或未知来源时回退为能力来源，避免错误归属。
4. 药水生成、升级、取回或自动打出的卡牌，后续伤害归实际造成伤害的卡牌，不回溯给药水。
5. 药水引导的充能球、召唤物或独立 Token，后续伤害归实际充能球、宠物或 Token，不回溯给药水。
6. 对他方玩家、友方宠物或药水使用者自身的伤害不计入对敌输出；能稳定识别时进入受到伤害或自损，不能识别时保留未知来源风险。
7. 同一药水多次使用、多个目标、升级或数值变化合并为一个稳定药水 ID；药水标题由运行时本地化提供。
8. 静态覆盖不等同于实机通过；凡依赖 `OnUseWrapper` 异步上下文、最近来源、随机目标、回合边界或多人所有权的项目均保留“待运行验证”状态。

### 药水本体对敌直接伤害

| 药水 | 药水池 | 静态效果 | 当前统计落点 | 状态 |
| --- | --- | --- | --- | --- |
| `ExplosiveAmpoule` | 通用 | 对敌方全体造成 10 点 `Unpowered` 伤害 | `PotionModel.OnUseWrapper` 压入药水模型，伤害可归药水 | 静态应为药水来源，待实机验证多目标 |
| `FirePotion` | 通用 | 对单个敌人造成 20 点 `Unpowered` 伤害 | 同上 | 静态应为药水来源，待实机验证 |
| `FoulPotion` | 事件 | 战斗中对所有非宠物生物造成 12 点 `Unpowered` 伤害；非战斗时在商人或假商人事件获得 100 金币 | 对敌部分可归药水；对玩家和友方部分应进入受到伤害或自损，而不是输出 | 代码目标是“所有非宠物”，需重点验证自身、友方和多人 |
| `PotionShapedRock` | Token | 对单个敌人造成 15 点 `Unpowered` 伤害 | `PotionModel` 模型链可命中，归药水 | 静态应为药水来源，待实机验证 |

- 4 个直接伤害药水全部使用 `ValueProp.Unpowered`，不会再次叠加力量等攻击力修正。
- 药水直接伤害的源码调用位于 `PotionModel.OnUseWrapper` 的 `PushModel(this)` 与最终 `PopModel(this)` 之间。当前 `DpsAttribution.SelectDirectModel()` 明确接受 `PotionModel`。
- `FoulPotion` 的 `TargetType.AllEnemies` 只描述目标选择界面；战斗分支实际传入的是 `CombatState.Creatures.Where(c => !c.IsPet)`，代码上会覆盖使用者本身和其他玩家。该差异必须结合实机确认。

- 药水施加能力时传入的 `CardModel? cardSource` 为 `null`。当前 `DpsHook.AfterPowerAmountChanged` 只把这个卡牌来源交给 `DpsAttribution.RecordPowerOrigin`。

- `DoomPower` 虽然被 `RecordPowerOrigin` 跟踪，但因为施加时没有卡牌来源，会记录为未知来源，无法稳定回溯 `PotionOfDoom`。

- `DemisePower` 发动前会调用 `Flash()`，最近来源可落到该能力；不过当前伤害能力白名单不含 `DemisePower`，且伤害的 `dealer` 为 `null`。目标是敌方时，`ResolveCategory` 预期返回 `Ignored`，因此当前实现存在明确漏计路径。

## 当前代码调用链与归因

### 药水本体直伤

`PotionModel.OnUseWrapper` 在调用 `OnUse` 前执行 `choiceContext.PushModel(this)`，并在使用结束后执行 `choiceContext.PopModel(this)`。本 Mod 的 `DpsSourceContext` 通过 Harmony Patch 记录这个模型栈，并在 `DpsAttribution` 中按以下顺序选择直接来源：

1. 优先从模型链中选择 `CardModel`、`RelicModel`、`PotionModel`、`OrbModel` 或 `EventModel`；
2. 模型链没有可用对象时，检查最近伤害型能力；
3. 检查最近遗物；
4. 检查最近药水；
5. 最后扫描目标、实施者和生命值上的能力回退。

因此 `ExplosiveAmpoule`、`FirePotion` 和 `PotionShapedRock` 的同步直接伤害具备药水来源路径。`FoulPotion` 也进入同一路径，但对友方和自身的伤害需要由目标分类决定是输出、受到伤害还是自损。

### 药水施加能力

`DpsHook.AfterPowerAmountChanged` 的签名只提供：

```csharp
CardModel? cardSource
```

`DpsAttribution.RecordPowerOrigin` 现在接收 `AbstractModel?`，并通过 `DpsSourceContext.GetCurrentEffect(applier)` 获取 `PotionModel` 等显式来源；快照保存显示名、内部 ID、来源类型和本次施加层数。当前具体行为如下：

| 能力 | 是否属于伤害能力白名单 | 是否记录来源 | 当前结果 |
| --- | --- | --- | --- |
| `PoisonPower` | 是 | 记录来源模型和施加层数 | 唯一来源时 `Tracked` 并保留药水；混合或未知来源为 `Deferred` |

| `DemisePower` | 否 | 不记录 | 预期不被识别为输出，存在漏计 |
| 其他药水能力 | 否 | 不记录 | 只影响后续伤害、格挡或资源，不单独计伤 |

### 代码异常与风险

- `PotionOfBinding` 的两个动态变量键发生交叉读取：

```csharp
await PowerCmd.Apply<WeakPower>(
    choiceContext, targets,
    base.DynamicVars["VulnerablePower"].IntValue,
    base.Owner.Creature, null);

await PowerCmd.Apply<VulnerablePower>(
    choiceContext, targets,
    base.DynamicVars["WeakPower"].IntValue,
    base.Owner.Creature, null);
```

当前 `WeakPower` 和 `VulnerablePower` 都配置为 1，因此暂时不影响实际数值；后续若升级数值或本地化调整，必须修正键名。

- `FoulPotion` 的战斗伤害目标为“所有非宠物生物”，不是只选择敌方。使用者自身和友方玩家可能同时受伤。
- `PowderedDemise` 的伤害来自 `DemisePower`，不是药水本体；当前能力白名单和来源字段都不覆盖该路径。
- `PoisonPower`、`DoomPower`、`ThornsPower` 的显示名称分别属于能力机制。若产品要求显示“由哪瓶药水施加”，仅靠当前卡牌来源字段不足。
- 直接伤害药水在 `OnUseWrapper` 的异步等待中仍保持模型栈，但 `FoulPotion` 和多人目标需要实机确认上下文没有被后续效果覆盖。

## 分类校验

- 主目录药水文件：64 个。
- 正式药水：63 个。
- 废弃药水：1 个，即 `DeprecatedPotion`，其 `Rarity` 为 `None`，未实现 `OnUse`。
- 测试药水：1 个，即 `MockDiscardAndAddShivsPotion`，只在 `MockPotionPool` 登记，不计入正式药水。
- 正式药水池登记：`45 + 3 + 3 + 3 + 3 + 3 + 2 + 1 = 63`。
- 包含废弃和测试的池登记总数：`63 + 1 + 1 = 65`。
- 药水本体对敌直接伤害：4 个。
- 施加伤害型能力：4 个。
- 生成卡牌、自动打牌、充能球或召唤物：11 个。
- 施加普通状态、伤害修正或资源型能力：22 个。
- 其他资源、牌堆规则与卡牌改造：22 个。
- 主要分类合计：`4 + 4 + 11 + 22 + 22 = 63`。
- 调用 `PowerCmd.Apply` 的正式药水：26 个；其中伤害型能力 4 个、普通能力 22 个。
- 逐药水编号：连续 `1..63`，内部类名唯一。
- 直接伤害药水调用：`CreatureCmd.Damage`。
- 派生伤害药水调用：`CardFactory`、`CardPileCmd`、`AutoPlayFromDrawPile`、`OrbCmd.Channel` 或 `OstyCmd.Summon`。

## 待游戏内验证

- `ExplosiveAmpoule`、`FirePotion`、`PotionShapedRock` 逐个验证右键使用后的来源名称、伤害数值、格挡吸收和过量伤害。
- `FoulPotion` 在单人、多人、自身、友方宠物和敌方同时受击时验证分类，确认自身和友方不会出现在对敌输出。
- `FoulPotion` 在商人和假商人事件中使用，确认只获得 100 金币且不产生 DPS 事件。
- `PoisonPotion` 分别验证唯一来源、重复施毒和多人混合来源：唯一来源应保留药水与层数，混合或未知来源应保留 `Deferred`，且不得误归给其他玩家或卡牌。
- `PotionOfDoom` 验证灾厄击杀是否记录击杀前生命，并确认来源应显示 `DoomPower` 还是 `PotionOfDoom`。
- `PowderedDemise` 在敌人回合结束时验证是否漏计；若漏计，需决定是否将 `DemisePower` 加入伤害能力白名单，并补充施加者来源。
- `LiquidBronze` 验证荆棘反伤仍归 `ThornsPower`，并确认药水来源和 3 层已写入来源快照；若 UI 仍不展示非卡牌来源，按技术债 TD-020 跟踪。
- `AttackPotion`、`ColorlessPotion`、`CosmicConcoction`、`CunningPotion`、`OrobicAcid`、`PotOfGhouls`、`PowerPotion`、`SkillPotion` 生成后实际打出，确认伤害归实际卡牌。
- `DistilledChaos` 连续自动打出攻击牌、能力牌和技能牌，确认嵌套模型栈下仍归实际卡牌。
- `EssenceOfDarkness` 验证暗球伤害归实际球体；`BoneBrew` 验证 Osty 伤害归宠物主人。
- `StrengthPotion` 与 `FlexPotion` 在攻击前后验证最终伤害：只记录攻击牌的最终伤害，不拆分力量加成来源。
- `PotionOfBinding` 在升级或数值变更场景下验证弱化和易伤层数；当前源码交叉使用动态变量键。
- 多人模式验证 `TargetType.AnyPlayer` 药水的目标所有权、宠物责任玩家和伤害归属。
- 所有药水在异步等待、暂停恢复和战斗结束时验证不会污染下一条伤害来源。

## 当前限制

- 本文结论来自 `0.107.1` 的静态审计，尚未完成逐药水游戏内验证。
- 直接伤害优先读取 `PotionModel.OnUseWrapper` 的显式药水来源栈，真实模型栈作为次级来源；异步等待、暂停恢复和战斗结束时仍需确认来源不会泄漏到下一条伤害。
- 药水施加的能力来源已写入 `PowerOriginSnapshot`；中毒能通过 `PoisonSourceInfo` 暴露唯一来源，`DoomPower` / `ThornsPower` 的非卡牌来源尚未单独展示。`DemisePower` 仍未纳入伤害白名单，当前预计漏计。
- `FoulPotion` 的战斗目标代码范围大于 `TargetType.AllEnemies`，自损和友方承伤分类需要实机日志确认。
- 药水生成牌、自动出牌、充能球和召唤物的静态归因已明确，但嵌套出牌链、多人所有权和宠物来源仍待运行验证。
- `PotionOfBinding` 的动态变量键读取交叉；当前数值都为 1，暂不改变统计结果，但属于后续升级风险。
- 力量、敏捷、易伤、虚弱等能力只影响最终结算。除非产品明确要求显示施加过程，否则不应把这些修正拆成独立伤害来源。

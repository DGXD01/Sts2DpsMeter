## 最终行为

| 项目 | 行为 |
| --- | --- |
| 缓存 | EndCombat 在现有锁内、PendingDoomKills 等清理前 GetSnapshot，冻结为 IsActive=false；重复结束沿用同一快照。未改变原本在 BeginCombat/ResetRun 清空 Players 的时机，未更改伤害、归因、计时或分摊公式 |
| 缓存寿命 | 只保留最近完成的一场；BeginCombat、ResetRun 清除，CombatId 防止把旧总结带入新战斗。每帧只读取状态与缓存引用，避免为总结不断分配全量快照 |
| 内容 | 五行：总结及范围、总伤害/DPS、最高来源及其总伤害、最大单次及来源、回合数/耗时。最高来源复用既有来源身份键合并、同值稳定排序；最大单次取已有玩家最大值，不把总伤害伪装成单次 |
| 范围 | 单人本场；多人固定全队并明确标注，用队伍完整总量和共享战斗时长。与用户当前 HUD 个人/回合/全队视图、模块开关、摘要字段、排序及行数无关；不改变 HUD 的选择 |
| 默认与设置 | 默认开启、5 秒；齿轮“战斗结束”可完全关闭，滑块 3–15 秒，含 3/5/8 秒。时长在下次总结生效；Schema 8、旧 Schema 4–7 保留原值，新字段完整接入 Clone/JSON/归一化 |
| 关闭与去重 | 每个结束 ID 消费一次，到时不重播；关闭开关/隐藏 HUD 后立即取消，再开启不补播。节点退出取消，重建不重播已消费的战斗。新战斗/新对局立即清除；空玩家战斗跳过 |
| 显示 | 复用已获用户确认的字体、2 倍采样与 UiScale、深色蓝标题；在 HUD 附近放置，复用已有边缘翻转/限制定位。来源按普通 Label 字面显示，移除换行并截断超长来源，每行最多两行，不解析 BBCode |
| 交互 | 浮层和全部子节点 MouseFilter.Ignore，无按钮/焦点或计时阻塞；不暂停游戏，不拦截奖励/地图点击。独立于 HUD 手动折叠和临时透明度，打开设置时隐藏但计时继续 |

发布后按以下步骤测试（本轮不操作游戏）：

1. **默认显示**：确认载入包含第六步的新版本。齿轮→战斗结束，保持开关开启、5 秒。结束一场单人战斗，检查总结出现并明确写本场；总伤害/最高来源/最大单次/回合数与战斗末尾统计一致，DPS 使用冻结的战斗时间。
2. **自动消失及不重播**：总结出现后约 5 秒消失，继续停留奖励页或地图不应重复出现；分别改为 3 秒、8 秒，在后续战斗检查对应时长。
3. **完全关闭**：关闭后结束战斗，不出现；总结显示期间关闭，应立即消失。随后重新开启，旧战斗不能补播，下一场结束才显示。
4. **下一场/新对局**：设 15 秒并尽快进入下一场，旧总结立即消失，下一场结束显示新数据；重开对局不残留旧总结。不能快速进入时暂留本项待验。
5. **鼠标穿透**：总结覆盖区域内若有奖励/地图目标，点击应照常生效；浮层不抓键盘焦点、不阻塞游戏，不需要先关闭浮层。
6. **设置与旧交互**：总结期间打开设置，应隐藏；计时仍继续，超时后关设置不能重播。检查手动折叠、低干扰恢复、边缘磁吸、详情/标题提示，以及关闭统计模块或改变 HUD 范围/排序不会把总结误改为单回合/截断总量。
7. **保存与显示**：开关/时长修改后重启应保留；复查中文/英文、长来源、常用缩放和屏幕边缘，不应溢出或过度遮挡。隐藏 HUD 不弹总结。
8. **多人统一测试**：总结明确标注全队，总伤害和最高来源来自完整团队、DPS 用共享时间、最大单次取最大；HUD 当前玩家选择不应被总结改变。与第五步测试一起完成。

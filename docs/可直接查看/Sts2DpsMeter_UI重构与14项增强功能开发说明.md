# Sts2DpsMeter UI 重构与 14 项增强功能开发说明

> **用途**：作为后续 AI / 开发者直接执行的 UI 重构总规范。
> 目标仓库：`DGXD01/Sts2DpsMeter`。本阶段重点是 UI、交互、设置与信息展示增强，不重写伤害归因核心。

## 1. 总体目标

将现有偏“大型数据面板”的 HUD 重构为 **紧凑、低遮挡、游戏化、富文本、模块化、可配置** 的战斗统计 HUD。

目标结构示意：

```text
┌────────────────────────────────────┐
│ ◀ 本场 · 47伤害 · 15.6DPS ▶ [本场▼] ⚙ − │
├────────────────────────────────────┤
│ ⚔ 打击       █████████████    39  83% │
│ ☠ 中毒       ███               8  17% │
│ ⚡ 闪电       ██                4   8% │
└────────────────────────────────────┘
```

### 视觉基线

- 深黑 / 蓝黑半透明背景。
- 蓝色标题强调、白色正文、灰白次要信息、红色伤害进度条。
- 小圆角、细边框、小体积右上角 HUD。
- 原有文字“设”按钮改为 **齿轮图标 `⚙`**。
- **删除暂停菜单“偏好设置”入口方案**；设置统一从 HUD 齿轮进入。

## 2. 架构与修改边界

必须保持当前数据流：

```text
DpsHook / DpsSourceContext
          ↓
DpsAttribution
          ↓
DpsStats
          ↓
CombatStatsSnapshot
          ↓
DpsMeterUi / DpsMeterSettingsUi
```

### 不允许破坏

- 输出伤害、承伤、自损、格挡、能量、队友辅助统计。
- 单人 / 多人统计。
- 本地玩家识别、职业颜色。
- 位置保存、缩放、CompactMode、MaxRows、折叠。
- 中英文、本地设置持久化、主线程安全刷新。
- 除非发现明确 Bug，否则不要为了 UI 重构修改 `DamageAttribution` 的归因逻辑。

## 3. 14 项增强功能

### UI-01 HUD 屏幕边缘磁吸

**目标：** 让 HUD 在拖动结束时自动吸附到屏幕边缘或角落，减少“差一点对齐”的视觉误差。

**实现要求：**

- 支持左上、右上、左下、右下、左/右边缘、顶部、底部吸附。
- 新增 SnapEnabled、SnapDistance、ScreenMargin 等设置；默认开启，吸附距离建议 20–30 px。
- 拖动过程中只提示候选吸附位置，松开鼠标后再执行最终吸附，避免跳动。
- 必须考虑 UiScale、分辨率变化和保存位置。

**验收标准：**

- [ ] 右上角/四角吸附准确
- [ ] 缩放后仍准确
- [ ] 重启后位置恢复
- [ ] 分辨率变化后不会跑出屏幕

### UI-02 战斗中自动降低干扰

**目标：** 在需要观察战场时临时降低 HUD 存在感，同时不改变用户永久设置。

**实现要求：**

- 至少支持：关闭、降低透明度、自动折叠。
- 临时透明度建议 25%–40%；退出低干扰状态后恢复用户原透明度。
- 自动折叠时只保留标题栏、Scope、齿轮和展开按钮。
- 后续可扩展到拖牌、瞄准敌人或鼠标离开 HUD 时触发。

**验收标准：**

- [ ] 三种模式可切换
- [ ] 不会改写 PanelOpacity 原值
- [ ] 折叠/恢复稳定
- [ ] 不会导致 HUD 消失后无法恢复

### UI-03 点击统计行展开详情

**目标：** 主 HUD 保持紧凑，同时允许用户按需查看单个来源的详细统计。

**实现要求：**

- 点击来源行后展开命中次数、最大伤害、平均伤害、格挡伤害、生命伤害、过量伤害等。
- 再次点击收起；建议默认只允许同时展开一个来源。
- 优先从 SourceStatsSnapshot / CardStatsSnapshot / MechanismStatsSnapshot 取数据。
- 若 Snapshot 缺字段，应在统计层新增只读字段，不允许 UI 直接访问可变统计容器。

**验收标准：**

- [ ] 展开/收起无错位
- [ ] 最多只展开设定数量
- [ ] Scope/玩家切换后详情正确
- [ ] 数据与统计核心一致

### UI-04 顶部摘要信息自定义

**目标：** 允许用户决定 HUD 标题栏显示哪些核心指标。

**实现要求：**

- 至少支持总伤害、DPS、DPT、承伤、回合数、命中次数。
- 建议最多同时显示 2–3 个指标，避免标题栏过长。
- 示例：本场战斗 · 47伤害 · 15.6 DPS。
- 设置页使用复选项控制字段。

**验收标准：**

- [ ] 所有字段可单独开关
- [ ] 标题过长时不破坏布局
- [ ] 不同 Scope 下含义正确
- [ ] 中英文文本均正常

### UI-05 重新定义统计范围 Scope

**目标：** 消除“总计”在单人和多人模式下语义不同的问题。

**实现要求：**

- 单人至少保留“本场战斗”“本回合”。
- 多人第三档建议明确命名为“全队”/“Team”，不再使用模糊的“总计”。
- 如未来真正加入 Run 级累计，再新增“本局累计 / Run Total”。
- 禁止把当前 Combat 数据伪装成 Run Total。

**验收标准：**

- [ ] 单人不出现重复语义 Scope
- [ ] 多人全队数据为全队当前战斗汇总
- [ ] 旧设置升级后不会崩溃

### UI-06 统计来源排序方式

**目标：** 让玩家根据不同分析目的选择来源排序方式。

**实现要求：**

- 至少支持总伤害、百分比、命中次数、最大伤害、名称、最近触发。
- 默认保持总伤害降序。
- 执行顺序必须是先排序，再应用 MaxRows。
- 排序仅影响显示，不修改底层统计。

**验收标准：**

- [ ] 切换排序立即生效
- [ ] MaxRows 仍正确
- [ ] 同值排序稳定
- [ ] 不会改变统计总数

### UI-07 来源类型图标

**目标：** 用小图标快速区分卡牌、状态、遗物、药水、球体、宠物等来源。

**实现要求：**

- 至少区分 Card、Power、Relic、Potion、Orb、Pet、Event、Unknown。
- 若没有正式资源，允许先用 Unicode、简单矢量图标或 Godot Theme Icon。
- 图标列必须固定宽度，不能因为有/无图标导致数值列错位。
- 新增“显示来源图标”开关。

**验收标准：**

- [ ] 所有 SourceType 有合理回退
- [ ] 关闭图标后列仍整齐
- [ ] 图标不影响文本裁切

### UI-08 悬停 Tooltip

**目标：** 在不扩大 HUD 常驻尺寸的前提下提供更多分析信息。

**实现要求：**

- 悬停来源行显示来源类型、总伤害、占比、命中、最大、平均、生命/格挡伤害等。
- Power 可显示机制与归因置信度。
- 增加 Tooltip 详细程度：简洁 / 详细 / 开发者。
- Exact / Inferred / Unknown 默认只应出现在开发者级别。

**验收标准：**

- [ ] Tooltip 不遮挡主要信息
- [ ] 移动鼠标后正常关闭
- [ ] 不同详细度内容正确
- [ ] 无数据字段时不显示无意义占位

### UI-09 多人模式快速查看方式

**目标：** 降低多人场景下切换统计对象的操作成本。

**实现要求：**

- 至少支持当前玩家、自己、全队三种视图。
- 继续保留左右箭头切换玩家。
- 新增“多人默认视图”设置。
- 本地玩家继续使用职业颜色并标记“（你）/(You)”。

**验收标准：**

- [ ] 自己/玩家/全队数据一致
- [ ] 左右箭头逻辑不冲突
- [ ] 进入多人战斗时默认视图正确

### UI-10 战斗结束总结浮层

**目标：** 战斗结束后短暂显示本场关键数据，让用户不必在战斗结束瞬间手动查看 HUD。

**实现要求：**

- 建议显示总伤害、DPS、最高来源、最大单次、回合数等。
- 默认显示 3–5 秒，并提供 3/5/8 秒或自定义持续时间。
- EndCombat 清空数据前必须缓存最终 Combat Snapshot。
- 总结浮层不能改变统计生命周期或阻塞游戏流程。

**验收标准：**

- [ ] 战斗结束后稳定出现
- [ ] 到时自动消失
- [ ] 下一场战斗不会显示旧数据
- [ ] 可完全关闭

### UI-11 HUD 预设布局

**目标：** 为普通用户提供一键可用的配置组合。

**实现要求：**

- 至少提供：极简、默认、详细、多人。
- 点击预设时把预设参数复制到当前设置，之后用户仍可单独修改。
- 禁止把 Preset 当成强制模式持续覆盖用户单项设置。
- 预设应覆盖显示模块、MaxRows、字段、图标、缩放等关键项。

**验收标准：**

- [ ] 四个预设结果可预测
- [ ] 预设后仍可手动修改
- [ ] 保存并重启后结果一致

### UI-12 HUD 主题系统

**目标：** 把颜色和基础样式从 DpsMeterUi 的硬编码常量中抽离，支持可切换主题。

**实现要求：**

- 第一阶段至少提供：默认深色、游戏融合、高对比。
- 建议新增 HudTheme 枚举和 ThemeDefinition。
- 颜色、边框、标题强调色、进度条、次要文字等统一从主题读取。
- 主题切换只影响视觉，不改变统计和布局语义。

**验收标准：**

- [ ] 三套主题切换即时生效
- [ ] 所有关键控件使用主题值
- [ ] 高对比主题可读性明显提升

### UI-13 UI 缩放与文字大小分离

**目标：** 允许保持 HUD 体积较小的同时单独放大文字，适配 2K/4K 和可访问性需求。

**实现要求：**

- 保留现有 UiScale。
- 新增 FontScale 或 TextSize，建议提供 80%、90%、100%、110%、125%、150%。
- 所有字体大小应基于 BaseFontSize × FontScale 计算。
- 逐步移除 12/13/14/16 等散落硬编码字号。

**验收标准：**

- [ ] UiScale 与 FontScale 可独立变化
- [ ] 4K 下文字清晰
- [ ] 放大文字后不会严重截断

### UI-14 可自定义显示字段

**目标：** 把固定的“名称 | 数值 | 百分比”升级为可配置的富文本数据列。

**实现要求：**

- 至少支持名称、数值、百分比、命中次数、最大伤害、平均伤害。
- 默认保持名称 + 数值 + 百分比。
- 使用容器或网格做列布局，禁止通过字符串补空格实现对齐。
- 不同字段组合下数值列必须保持稳定对齐。

**验收标准：**

- [ ] 任意字段组合不破版
- [ ] 数值列右对齐
- [ ] 名称列可省略但仍能识别行
- [ ] 中英文长度变化可适配

## 4. 磁吸式富文本布局规范

这里的“磁吸”指字段自动吸附到稳定列位，不是物理动画。

禁止：

```csharp
$"{name}     {damage}      {percentage}%"
```

推荐结构：

```text
Row
├── IconColumn        固定宽度
├── NameColumn        左对齐 / ExpandFill
├── Spacer
├── HitsColumn        右对齐 / 固定宽
├── DamageColumn      右对齐 / 固定宽
└── PercentageColumn  右对齐 / 固定宽
```

示例：

```text
⚔ 打击                 39   83%
☠ 中毒                  8   17%
⚡ 闪电                  3    6%
```

无论名称长度、语言或字段组合如何变化，数字列都必须保持稳定对齐。

## 6. Settings Schema 建议

- 本次属于一次完整 UI 重构，建议把设置 Schema 从当前版本统一提升到一个新版本（建议 `5`）。
- 旧 `settings.json` 必须可继续加载；缺失的新字段使用安全默认值。
- 优先使用枚举而不是魔法数字。

建议新增字段：

```text
SnapEnabled / SnapDistance
AutoInterferenceMode
SummaryShowDamage / SummaryShowDps / SummaryShowDpt / SummaryShowTaken / SummaryShowHits
SourceSortMode / ShowSourceIcons
TooltipDetailMode
MultiplayerDefaultView
ShowCombatSummary / CombatSummaryDuration
HudTheme / FontScale
ShowFieldName / ShowFieldDamage / ShowFieldPercentage / ShowFieldHits / ShowFieldMaxHit / ShowFieldAverage
```

## 7. 性能要求

当前 HUD 存在 `Refresh() → ClearChildren() → 全量重建` 的性能风险。增强功能加入 Tooltip、图标、展开行和更多字段后，应优先减少无意义的全量节点重建。

推荐方向：

```text
初始化 HUD
    ↓
创建/复用 Row Pool
    ↓
数据变化
    ↓
只更新 Text / Value / Visible
```

如果暂时不能完成完整 Row Pool，至少应做到：数据没有变化时不重建内容，并合并同一帧内的多次刷新。

## 8. 推荐开发顺序

1. 重构 HUD 行布局 + 齿轮按钮 + 富文本列
2. 来源图标 + Tooltip + 可选字段
3. 排序 + 标题摘要配置 + Scope 语义调整
4. 边缘磁吸 + 自动降低干扰
5. 多人快速视图
6. 战斗结束总结
7. HUD 预设
8. 主题系统
9. FontScale
10. 设置面板重新分组与最终清理

每个阶段都应执行：`build → 静态检查 → 游戏内运行测试 → 再进入下一阶段`。

## 11. 交给其他 AI 的最终执行指令

> 1. 先完整读取仓库并理解现有 `DpsStats → CombatStatsSnapshot → DpsMeterUi → DpsMeterSettings` 数据流。
> 2. 不允许脱离现有架构重新造一套 UI 系统。
> 3. 本阶段重点是 UI、交互、配置和展示增强，不重写 `DamageAttribution`。
> 4. 每新增一个功能，都必须同步考虑：默认值、设置持久化、中英文、多人数值、缩放、折叠、不同分辨率。
> 5. 设置入口统一使用 HUD 齿轮；禁止向暂停菜单增加“偏好设置”按钮。
> 6. 所有增强功能尽量可关闭，使用户仍能保留接近旧版的简洁 HUD。
> 7. 开发应按阶段进行，每次只实现 1–3 个功能，完成构建与运行验证后再继续。
> 8. 最终目标：一个紧凑、可配置、富文本、低遮挡，并适合单人和多人战斗的原生感统计 HUD。

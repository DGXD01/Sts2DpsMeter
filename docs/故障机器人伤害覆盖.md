# 故障机器人单人卡牌伤害覆盖

## 基线

- 游戏程序集：`E:\STEAM\steam\steamapps\common\Slay the Spire 2\data_sts2_windows_x86_64\sts2.dll`
- 游戏版本：`0.107.1`
- 卡池来源：`MegaCrit.Sts2.Core.Models.CardPools.DefectCardPool`
- 卡池数量：88 张
- 当前范围：故障机器人单人卡牌；多人归属和敌方能力来源另行验证
- 数据整理日期：2026-09-19

本文档记录从游戏程序集反编译得到的伤害指令，以及 Mod 当前采用的归因方式。卡名以游戏内部类名为准；统计显示名使用游戏运行时提供的本地化标题。

## 统计原则

1. 同一张卡牌的多次命中、多个目标和升级版本合并为一个统计类型，使用稳定卡牌 ID 聚合。
2. 直接伤害由 `DamageCmd.Attack(...).FromCard(this)` 或携带卡牌上下文的 `CreatureCmd.Damage` 产生，直接归因到实际卡牌。
3. 充能球伤害归入实际 `OrbModel`；通道、激发、被动和 `LoopPower` 等触发方式只作为触发链路，不把球伤害改写为通道卡牌本身。
4. 能力间接伤害只在能力能够稳定确定唯一来源卡牌时写入 `PowerOriginCardTypes`。本次补充 `HailstormPower`、`SmokestackPower`、`ThunderPower` 三条映射。
5. 自动打出、生成、克隆或转换得到的卡牌，按实际被打出的卡牌稳定 ID 统计；不回溯给生成它的卡牌。
6. 状态牌 `Dazed`、`Slimed`、`Wound`、`Burn`、`Void` 不产生伤害；它们只作为生成、弃牌或抽牌结果进入后续链路。
7. `ThunderPower` 在闪电球激发后追加伤害；验证时需要确认激发卡牌链与 `Thunder` 静态映射的优先级。

## 代码覆盖结果

### 直接伤害

游戏程序集中共有 29 张故障机器人卡牌包含直接伤害指令：

`AdaptiveStrike`、`AllForOne`、`BallLightning`、`Barrage`、`BeamCell`、`Claw`、`ColdSnap`、`CompileDriver`、`FlakCannon`、`FocusedStrike`、`Ftl`、`GoForTheEyes`、`GunkUp`、`HelixDrill`、`Hyperbeam`、`IceLance`、`MeteorStrike`、`MomentumStrike`、`Null`、`Refract`、`RocketPunch`、`Scrape`、`Shatter`、`StrikeDefect`、`Sunder`、`SweepingBeam`、`Synthesis`、`TeslaCoil`、`Uproar`。

这些路径由 `DamageCmd` 或带卡牌上下文的伤害指令携带稳定卡牌来源，不需要在 `DpsAttribution` 中逐张硬编码；卡牌名、升级版本和同名合并由统计层处理。

### 充能球伤害

| `DarkOrb` | 不立即伤害；给激发值增加 6 点基础值 | 对最低生命敌人造成累计激发伤害 | 实际 `DarkOrb` |

| `FrostOrb` | 提供格挡 | 提供格挡 | 不产生伤害事件 |
| `PlasmaOrb` | 提供能量 | 提供能量 | 不产生伤害事件 |

通道伤害卡：`BallLightning`、`Chill`、`ColdSnap`、`ConsumingShadow`、`Coolheaded`、`Darkness`、`Fusion`、`Glacier`、`Glasswork`、`IceLance`、`Ignition`、`MeteorStrike`、`Null`、`Rainbow`、`Refract`、`ShadowShield`、`Spinner`、`Tempest`、`Voltaic`、`Zap`。

激发卡：`Dualcast`、`MultiCast`、`Quadcast`、`Shatter`。`Shatter` 还会先造成一次直接攻击。

被动/能力触发：`TeslaCoil` 直接攻击后触发闪电被动；`LoopPower` 在回合开始时触发最前面的球；`ConsumingShadowPower` 在回合结束时逐次激发最后一个球；`LightningRodPower`、`SpinnerPower`、`StormPower`、`TrashToTreasurePower` 负责生成或触发球，伤害归实际球。归因层监听 `OrbModel.Trigger()`，覆盖回合结束直接调用 `OrbModel.Passive` 时不经过 `OrbCmd.Passive` 模型栈的路径。

### 自动出牌、生成与状态边界

- `AdaptiveStrike` 造成直接伤害后生成自身的 0 费克隆牌；后续打出该克隆牌仍按 `AdaptiveStrike` 统计。
- `BoostAway`、`FightThrough`、`GunkUp`、`Overclock`、`Turbo` 生成 `Dazed`、`Wound`、`Slimed`、`Burn`、`Void` 等状态牌；状态牌本身不产生伤害。
- `Uproar` 先造成伤害，随后自动打出相关卡牌；自动打出的卡牌按实际卡牌 ID 统计。
- `WhiteNoise`、`CreativeAi` 会生成或打出其他卡牌；其后的伤害按实际被打出的卡牌统计。
- 球栏位增减、聚焦、能力倍率、费用和重放次数只改变结算数值或次数，不改变球的伤害来源。

## 运行态验证清单

- 直接伤害卡：验证多段、群体、过量和目标死亡的统计是否分别正确累加。
- 通道与激发：验证 `LightningOrb`、`DarkOrb`、`GlassOrb` 的被动和激发伤害在 `Dualcast`、`MultiCast`、`Quadcast`、`Shatter` 中的实际落点。
- 能力间接伤害：分别验证 `Hailstorm`、`Smokestack`、`Thunder` 的来源卡牌映射与触发卡牌显示。
- 生成牌边界：验证状态牌不产生伤害，克隆牌和自动出牌按实际卡牌 ID 统计。
- 多人与敌方来源：验证玩家 NetId、宠物归属以及敌方施加状态造成的伤害口径。

## 当前限制

- 本文档和代码基于静态反编译审计，尚未完成逐项游戏内运行验证。
- `Chaos` 等动态随机通道、`ThunderPower` 在复杂自动出牌链中的触发来源，需要以实机日志确认。
- `FrostOrb` 和 `PlasmaOrb` 只提供格挡或能量，因此不会出现在 DPS 的伤害事件中。
